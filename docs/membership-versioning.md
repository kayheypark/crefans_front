## 지킬 정책

멤버십 수정은 **새로 가입하는 사람에게 적용할 새 조건을 발행하는 일**이다. 기존 구독자가 동의한 가격·결제 주기·혜택·이용 권한은 유지한다. 신규 가입 중단도 기존 계약의 중단을 의미하지 않는다.

버전 번호는 내부 식별 정보다. 크리에이터에게 버전 선택을 맡기지 않고 서버가 발행 시 부여한다. 편집 화면에서는 “변경 사항은 신규 구독부터 적용되며 기존 구독 조건은 유지됩니다”라는 안내를 유지한다. 크리에이터용 변경 이력 조회와 팬에게 공개할 조건 이력은 후속 범위다.

## 현재 확인된 구현과 차이

| 영역 | 현재 구현 | 아직 보장하지 못하는 것 |
| --- | --- | --- |
| 프론트 스튜디오 목업 | `saveMembership`가 이름·가격·혜택을 저장하면서 `version`을 증가시킨다. 구독자는 별도 `planSnapshot`의 가입 당시 이름·가격·혜택·버전을 표시한다. | 이전 판매 버전 목록을 저장하지 않는다. 세션 상태이며 영속성·동시 수정 방지·서버 권한 검증은 아니다. |
| 서버 상품 | `MembershipItem` 한 행에 가격·주기·혜택·레벨이 있고 `updateMembership`가 그 행을 직접 수정한다. 수정 시 소유권은 확인한다. | 불변 버전 테이블·변경 이력·구독의 버전 참조가 없다. |
| 서버 가입·첫 결제 | 가입 준비 때 현재 상품 조건을 반환하고, 승인 때 상품을 다시 조회해 `Subscription.amount` 및 결제 금액을 저장한다. | 사용자가 본 조건과 승인 시점 조건을 연결하는 버전·견적이 없다. 두 시점 사이의 수정으로 금액이나 조건이 달라질 수 있다. |
| 서버 정기결제 | 서버 메서드와 별도 Lambda 모두 `Subscription.amount`로 결제하므로 기존 구독 금액은 별도 보존된다. | 다음 결제일 계산은 수정 가능한 `membership_item.billing_period/billing_unit`을 사용한다. 가격 보존만으로 계약 전체가 보존되지는 않는다. |
| 서버 권한·조회 | 구독에서 현재 `membership_item`의 이름·레벨을 조회한다. 일부 접근 검사에는 상품의 `is_active/is_deleted`도 포함된다. | 상품 수정·신규 판매 중단이 기존 구독의 표시나 권한에 영향을 줄 수 있다. 각 접근 경로를 동일한 계약 기준으로 맞춰야 한다. |
| 결제 기록 | `PaymentTransaction`에 주문번호·결제금액·구독 연결·상태가 있고 주문번호와 결제키가 고유하다. | 해당 거래가 어떤 멤버십 버전과 조건으로 승인됐는지 자체 스냅샷이 없다. 주문번호 고유성만으로 같은 갱신 회차의 중복 결제를 막는 것은 아니다. |

따라서 프론트 목업의 “기존 조건 유지”는 목표 정책의 시연이다. 현재 서버 전체에 이미 적용된 보장으로 설명해서는 안 된다.

## 저장 구조

| 객체 | 보존할 값과 역할 |
| --- | --- |
| `Membership` | 영속적인 상품 ID, 소유 크리에이터, 현재 판매 버전 ID, 신규 가입 가능 여부. 수정해도 상품 ID는 유지한다. |
| `MembershipVersion` | 상품 ID, 서버가 부여한 순번, 이름·설명·통화·가격·결제 단위/주기·체험 조건·혜택 목록·권한 정의, 발행 시각·발행자. 발행 후 내용 수정·삭제를 금지한다. |
| `Subscription` | 상품 ID와 **가입 당시 버전 ID**를 함께 참조한다. 계약 금액·통화·주기·동의 시각·조건 스냅샷, 이용 시작/종료, 다음 갱신 시각은 구독 계약의 값이다. |
| `CheckoutQuote` | 사용자, 상품·버전, 제시한 전체 조건, 금액·통화·세금/할인 적용 결과, 만료 시각, 사용 여부. 서버가 생성하며 클라이언트 금액을 신뢰하지 않는다. |
| `PaymentOrder` / 거래 기록 | 구독·버전·견적 참조, 결제 회차, 실제 청구 조건과 금액의 불변 스냅샷, 멱등 키·상태. 상품의 현재 표시 내용을 다시 읽어 과거 결제를 설명하지 않는다. |
| 발행 감사 기록 | 이전/새 버전, 변경 필드, 발행자, 발행 시각, 요청 식별자. 내부 변경 사유는 공개 조건과 분리한다. |

버전은 `unique(membership_id, version_number)`로 중복을 막는다. 현재 버전 포인터와 구독 버전이 같은 상품 소속인지도 제약 또는 트랜잭션 검증으로 보장한다. 혜택은 현재의 콤마 구분 문자열 대신 순서가 있는 구조화 목록으로 보존한다.

혜택 문구만 복사해서는 권한이 고정되지 않는다. 콘텐츠·메시지 등의 권한 판단 역시 구독에 연결된 버전의 권한 정의를 사용해야 한다. 판매 상태와 이미 성립한 구독의 이용 권한은 분리한다.

## 발행·가입·갱신 흐름

1. **발행:** 크리에이터 소유권을 검증하고 `expectedCurrentVersionId`를 비교한다. 변경이 있으면 새 버전 생성, 현재 버전 포인터 변경, 감사 기록을 하나의 DB 트랜잭션으로 처리한다. 동시 수정이면 충돌을 반환하고 재확인을 받는다. 내용이 같으면 불필요한 새 버전을 만들지 않는다.
2. **가입 준비:** 서버가 현재 판매 버전의 조건으로 만료 시각이 있는 견적을 만든다. 응답은 공통 `success/data/errorMessage/errorCode` 형식으로 전달한다.
3. **결제 확정 전:** 사용자·견적 소유권·만료·신규 판매 가능 여부와 버전을 다시 확인한다. 견적 이후 새 조건이 발행됐다면 `MEMBERSHIP_VERSION_CHANGED` 충돌로 돌아가 새 조건을 확인하게 한다. 다른 가격으로 조용히 결제하지 않는다.
4. **결제 주문 확정:** 검증과 주문 예약을 원자적으로 처리한다. 예약된 주문은 고정된 버전·금액으로만 승인한다. 외부 결제 요청에는 같은 논리적 주문의 멱등 키를 재사용하고, 외부 승인과 DB 반영 사이 장애는 조회·재조정으로 복구한다. 외부 결제가 DB 롤백으로 취소된다고 가정하지 않는다.
5. **가입 완료:** 검증한 주문의 버전에 구독을 고정하고 조건 스냅샷을 남긴다. 같은 주문의 재호출·웹훅은 구독을 중복 생성하지 않는다.
6. **갱신:** 현재 판매 버전이 아니라 구독에 고정된 가격·결제 주기·혜택으로 갱신한다. `(subscription_id, billing_cycle)` 고유 회차로 서버/Lambda 중복 실행을 막는다. 두 실행 경로를 동시에 운영한다면 동일한 회차 예약과 처리 규칙을 공유해야 한다.

기존 구독의 새 버전 전환은 별도 동의·적용 시각·변경 이력을 갖는 후속 기능이다. 단순 상품 수정이 구독의 버전 포인터를 변경해서는 안 된다. 할인·쿠폰을 도입하면 실제 계약 금액의 근거도 별도 보존한다.

## 이력 공개 범위

- 크리에이터: 자신이 소유한 멤버십의 발행 시각·조건 변화·적용 대상과 구독자가 가입한 조건을 조회한다. 목록·상세 모두 서버에서 소유권을 검사하며 수정 가능한 이력으로 제공하지 않는다.
- 팬: 후속 요청이 생기면 자신의 계약 조건과 공개가 허용된 판매 조건 이력을 제공한다. 공개 필드는 이름·가격·주기·혜택·적용 시각 등 허용 목록으로 제한한다.
- 다른 팬의 개인정보, 결제정보·빌링키, 직원 식별 정보, 내부 메모·감사 요청 정보는 공개 응답에 포함하지 않는다. 크리에이터용 원본 객체를 팬에게 그대로 반환하지 않는다.

## 기존 데이터 이전

### 활성화·삭제·이미지 연결

- 상품의 단일 `active` 플래그가 공개 프로필 노출과 신규 가입 허용을 함께 제어한다. 비활성화는 기존 구독 해지가 아니며 가입 당시 조건·갱신·이용 권한을 변경하지 않는다. 숨겨진 상품을 직접 호출한 신규 가입 요청도 서버가 거절한다.
- 삭제는 현재 이용 가능한 구독자가 없을 때만 허용한다. 자동 갱신을 해지했어도 이용 기간이 남아 있으면 현재 구독자로 계산한다. 클라이언트의 버튼 유무만으로 권한을 판단하지 않고 서버가 가입일·종료일·구독 상태를 재검사한다.
- 삭제 시 현재 판매 목록에서는 제거하지만 상품 식별자·버전·과거 구독·결제·감사 기록은 보존한다. 삭제된 상품의 재가입/발행은 차단한다. 판매 중단/삭제와 동시 신규 가입 주문 사이에는 잠금 또는 동일 트랜잭션 상태 검사를 두고, 승인 진행 중인 주문의 처리 정책을 확정하기 전 물리 삭제하지 않는다.
- 대표 이미지는 버전의 선택 필드로 `mediaId`를 참조한다. 새 버전에서 이미지를 바꿔도 기존 버전의 이미지를 덮어쓰거나 사용 중인 파일을 삭제하지 않는다. 미디어 보존·정리는 [별도 수명주기 설계](./media-lifecycle.md)를 따른다.

1. 새 구조를 추가하되 기존 읽기·결제를 즉시 제거하지 않는다. 상품별 현재 상태를 초기 버전으로 만들고, 이전 전/후 금액·구독 수·갱신 일정을 대조한다.
2. 기존 구독은 `Subscription.amount`, 결제 기록, 보존된 동의 자료에서 **확인 가능한 조건만** 이전한다. 현재 상품의 가격·혜택을 모든 과거 구독에 소급 복사하지 않는다.
3. 과거 혜택·주기를 복원할 근거가 없으면 `legacy/unknown` 출처와 미확인 필드를 명시한다. 금액은 보존하되 불확실한 조건을 확정된 과거 계약처럼 표시하거나 새 주기로 자동 변경하지 않는다. 예외 검토 없이 일괄 자동 갱신 전환하지 않는다.
4. 초기 이행 중에는 구독의 버전 연결 여부로 읽기 경로를 분기하고 비교 기록을 남긴다. 반복 실행 가능한 백필, 단계별 전환, 기능 플래그와 되돌림 경로를 준비한다.
5. 원장 대조와 예외 확인 후 신규 가입부터 새 구조로 전환한다. 기존 가입자의 계약 연결이 검증된 뒤 갱신·권한 조회를 전환한다.

## 후속 구현의 검수 기준

- 상품 가격·혜택·주기를 수정해도 기존 구독의 표시·청구·권한·갱신일이 변하지 않는다.
- 신규 가입은 새 버전을 사용하고, 동시에 발행해도 버전 순번과 현재 버전 포인터가 일치한다.
- 가입 준비와 승인 사이의 수정은 재확인으로 이어지며 임의의 새 금액으로 결제되지 않는다.
- 동일 주문·갱신 회차의 재시도와 중복 워커에서 한 번만 청구·구독 생성된다. 외부 승인 후 DB 장애도 재조정 가능하다.
- 신규 가입 중단 후에도 유효한 기존 구독은 권한을 유지한다. 해지·만료·전액 환불은 각 계약 상태에 따라 별도로 처리한다.
- 이력 접근 권한, 팬 공개 필드 제한, 근거 없는 과거 조건의 미확인 표시를 확인한다.
