# CREFANS 화면 검수

초기 제작 브랜치 `feat/ui-redesign`의 작업을 현재 개발 기준에 통합했다. 브랜치 이름은 구현 계약이 아니며 현재 상태는 `PROGRESS.md`와 Git에서 확인한다. 첨부된 팬 서비스 목업의 구성과 전체 서비스 계층도를 기준으로 만든 실제 Next.js 페이지다. 브랜드는 선택한 두 조각 하트 로고, 블루 CTA, 딥 블루 보조색, 잉크 네이비 글자로 통일했다. `/preview/screens`에서 팬·스튜디오·공통 화면을 탐색한다. 운영 API나 결제·메일·은행 이체는 호출하지 않는다.

모든 `/preview/*` 화면의 목업 안내는 공통 레이아웃 최상단의 작은 `목업 페이지입니다` 띠배너 하나로 통일한다. 팬·인증·랜딩·스튜디오 안의 중복 안내와 검수 목록 바로가기는 제거했다. 각 화면의 입력 도움말·오류·계약 조건·권한 안내는 유지하며 실제 사용자의 탐색 동선을 따른다. 화면 목록이 필요하면 `/preview/screens`로 직접 접속한다.

## 공통 기능

가입·로그인: `/preview/signup`(이메일 인증 코드·PASS 본인인증 모달을 같은 화면에서 완료해야 가입 가능), `/preview/login`. 두 화면 모두 일반 헤더를 쓴다. 회원가입에는 이탈 유도 링크를 두지 않고, 로그인에만 하단 메인으로 돌아가기 링크가 있다. 인증 코드는 10분 유효, 재전송 3분 쿨다운.
인증: `/preview/reset-password`(별도 이메일 인증 화면은 없다. 이메일 인증은 회원가입 안에서만 진행). 코드 `123456`은 화면에 공개한 검수용 코드이며 실제 보안 기능이 아니다.
지원: `/preview/support`의 FAQ와 `?tab=qna`의 개인 문의 등록·목록·상세.
안내: `/preview/notices`와 `/preview/notices/welcome`.
정책: `/preview/legal/terms`, `/preview/legal/privacy`, `/preview/legal/policy`. 확정 법률 문서가 없는 상태를 명시한 문서 레이아웃이며 임의의 계약을 운영 정책으로 게시하지 않았다.

## 데이터와 UI 계약

```text
목업 fixture / 실제 API 응답
          ↓
컨테이너·기능 모델 (래퍼 처리, 데이터 변환, 상태, 액션)
          ↓ props
공통 표시 컴포넌트 (components/crefans)
```

- 팬·공통·스튜디오 화면 모두 props로 데이터와 동작을 주입한다. 뷰는 fixture, PreviewProvider, fetch/API 모듈을 import하지 않는다.
- 목업의 조회·변경·초기화는 `components/preview/service`와 `components/preview/studio`의 Provider/모델에서 담당한다. 페이지 이동 동안 상태를 유지하며 새로고침하면 초기화한다.
- 재사용 계약은 `types/crefans*.ts`, 디자인 토큰은 `lib/design/tokens.ts`, 로고는 `components/crefans/Brand.tsx`에서 분리한다.
- 아래 래퍼는 신규 `/api/v1`과 실제 모델에 적용된 공통 계약이다. 기존 비버전 런타임은 별개이며 바이너리 미디어 성공 응답은 JSON 예외다.

```ts
type ApiResult<T> =
  | { success: true; data: T; errorMessage: null; errorCode: null }
  | { success: false; data: null; errorMessage: string; errorCode: string };
```

`ApiState`는 조회 성공/실패/로딩을 분기한다. 변경 콜백도 같은 래퍼를 반환하며 실패 시 입력을 유지하고 제공된 오류를 표시한다. 빈 목록과 누락된 참조는 샘플 값으로 메우지 않는다. 잠긴 게시물은 이미지 원본 src·본문·댓글을 표시하지 않는다. `/service`에서는 서버가 본문·댓글·미디어 권한을 실제 검증한다. 목업 통과는 실제 권한 검증의 증거가 아니다.

## 이름 규칙

- 메뉴·목록 항목명과 도착 페이지의 제목을 맞춘다. 홈은 사용자 지시로 제목을 숨기는 예외다. 팬 사이드바(홈·탐색하기·메시지·알림·내 프로필), 하단 링크(고객센터·공지사항·크리에이터 스튜디오), 설정의 모아보기·알림과 결제 목록(팔로잉 목록·저장한 게시물·좋아요한 게시물·내 구독·결제 내역·결제수단 관리)이 그대로 페이지 제목이다. 구독 페이지 제목은 탭에 따라 내 구독 / 결제 내역.
- 스튜디오 페이지 제목은 사이드바 라벨과 같다(대시보드·게시물·댓글·멤버십·구독자·메시지·통계 요약·순수익/구독자/팔로워 리포트·수익 현황·정산 내역·출금 신청·출금 내역·정산 계좌·출금 PIN 설정·크리에이터 설정).

## 제출 버튼 규칙

- 제출·저장·다음 단계 같은 주 버튼은 필수 입력이 모두 유효해질 때까지 `disabled`(흐림 + not-allowed 커서)이며 클릭되지 않는다. 핸들러 안의 검증은 이중 안전장치로 유지한다.
- 적용 폼: 회원가입(이메일·비밀번호 8자·닉네임·필수 동의), 로그인, 프로필 수정(닉네임), 계정 설정 패널(닉네임/이메일/비밀번호 3종), 문의 등록, 이메일 인증·비밀번호 재설정(이메일·코드·비밀번호), 댓글·답글·메시지 입력, 크리에이터 시작하기·크리에이터 설정(활동명·주소 형식·분야), 게시물 편집(제목, 게시·예약은 본문·예약 시각까지), 멤버십 저장(이름·가격·혜택 1개 이상), 출금 요청(금액 범위·계좌), 출금 PIN 확인·설정(6자리·일치), 정산 계좌(은행·예금주·끝 4자리), 멤버십 가입·회원 탈퇴 확인(동의 체크).

## 여백 규칙

- 기본 팬 셸 `.main`: PC 24px 36px 72px, 1000px 이하 24px 24px 64px, 767px 이하 20px 16px 100px. 페이지에서 동일 좌우 패딩을 다시 넣지 않는다.
- PC 공개 프로필·로그인한 내 프로필 기본 탭은 `.flushMain`으로 상단·왼쪽 여백을 0으로 한다. 저장/좋아요 탭과 비로그인 내 프로필의 로그인 안내는 기본 여백을 유지한다. 모바일 프로필 커버/피드 카드 미디어·구분선은 음수 margin으로 전폭 처리한다. 피드·프로필 읽기 폭은 최대 480px이다. 홈 피드에 게시물이 없으면 빈 상태 래퍼는 본문 가용 폭 전체를 사용해 안내를 가운데 정렬한다.
- 인증 `.authMain`: PC 20px 24px 64px, 모바일 12px 20px 40px. PC 로그인 필요 안내는 가운데 읽기 폭으로 표시한다.
- 스튜디오는 별도 `studio.module.css` 셸이 여백을 소유한다. 페이지 래퍼의 좌우 중복 패딩을 피하며 768px 미만은 지원 안내로 대체한다. 세부 값의 근거는 해당 CSS와 `ServiceShell`/`StudioShell`이다.

## 계층도 검토와 보완

팬 / 크리에이터 / 공통의 3영역 구분을 유지했다. 세부 항목이 모두 별도 URL일 필요는 없으므로 조건 선택은 탭, 영수증·가입자·정산 상세와 확인은 모달, 작성·출금·인증 흐름은 전용 화면으로 구성했다.

1. **계정과 역할**: 같은 검수 세션에서 팬과 스튜디오를 전환한다. 공개 활동 프로필은 일반 계정 설정과 분리한다.
2. **구독과 갱신 해지**: 갱신 해지 후에도 이용 기간이 남으면 접근을 유지한다. 만료는 별도 상태다.
3. **멤버십 변경**: 신규 가입 조건과 기존 구독자의 가입 당시 가격·혜택 snapshot을 분리했다. 단일 활성화 스위치가 공개 노출과 신규 가입을 함께 제어한다. 비활성화는 기존 구독 해지가 아니며 삭제는 현재 이용 가능한 구독자가 없을 때만 허용한다. 과거 구독 기록은 보존한다. 신규 플랫폼은 버전 기록·주문/구독 snapshot을 구현했다. 구형 런타임과 차이 및 추가 설계는 [버전 관리](./membership-versioning.md)를 따른다. 운영 이관은 미검증이다.
4. **콘텐츠 상태**: 임시저장·예약·발행을 분리하고 과거 시각 예약과 잘못된 공개 범위를 막는다. 예약 취소 후 임시저장을 명시한다.
5. **수익과 출금**: 순수익 = 정산 대기 + 출금 가능 + 출금 요청/처리 중 + 지급 완료. 반려 요청은 잔액을 계속 점유하지 않는다. 요청 확인 시와 접수 시 잔액·계좌를 다시 검사하며 같은 요청 키 재전송은 중복 차감하지 않는다.
6. **결제수단과 정산 계좌**: 팬의 결제 수단과 크리에이터의 수령 계좌는 서로 다른 화면·모델이다. 목업에서 실 계좌번호/카드번호를 수집하지 않는다.
7. **소통**: 팬/크리에이터 인박스는 동일 UI를 재사용하며 상대·문구·동작만 다르게 주입한다. 댓글 숨김과 원본 삭제를 구분한다.
8. **팬 화면 보완**: 팔로잉, 결제수단, 인증 완료/재설정, 공지·정책 문서 진입을 추가했다.

`/preview/studio`는 검수용 메모리 모델이며 실제 DB와 동기화하지 않는다. `/service/studio`는 동일 UI에 실제 권한·원장·업로드·가입/인증 API를 연결한다. 코드 연결과 운영 공급사/보안 감사 완료를 구분한다.

## 추가 검수 항목 (2026-09-13)

- 대시보드 지표에서 3개 리포트로 이동한다. 기간은 `~`로 연결하고 기간 변경 시 차트 데이터를 애니메이션으로 갱신한다. 대시보드 팔로워 지표는 `{인원수}명` 고정 포맷이며 팬 표시(`12.4K`)는 바꾸지 않는다.
- 스튜디오는 768px 미만 뷰포트에서 "모바일에서는 지원하지 않습니다" 안내만 표시한다. 팬 화면은 모바일을 지원한다.
- 리포트는 프리셋 외에 시작일·종료일을 직접 지정하고 `기간 적용`으로 조회한다. 요약·차트·목록은 같은 범위를 사용하며 구독자·팔로워 규모는 선택한 종료일을 기준으로 한다. 이력이 없는 구간은 임의 보간하지 않고 `기록 없음`과 제공 범위를 표시한다. 잘못된 날짜·역전 구간·미래 구간은 적용하지 않는다.
- 스튜디오 메뉴는 대시보드와 콘텐츠(연필: 게시물·댓글) / 멤버십(멤버십) / 구독자 관리(구독자·메시지) / 리포트 / 수익,정산,출금 관리 / 설정(톱니바퀴)으로 묶는다. 현재 페이지의 그룹을 자동으로 연다.
- 입력·선택 카탈로그에 혜택 목록, 금액 프리셋, PIN 입력을 등록한다. 모달 액션은 오른쪽, 스낵바는 4초의 남은 시간을 3px 바로 표시한다. 일반 링크는 파란 밑줄, 버튼과 클릭 가능한 행은 hover/focus 상태가 있다.
- 멤버십 이미지 업로드는 로컬 체험이며 공유 카드에 주입한다. 별도 멤버십 미리보기 버튼/화면은 사용자 요청으로 만들지 않는다. 게시물 미리보기는 팬 상세 UI를 재사용하는 별개 기능이다.
- 게시물 목록·작성 화면의 미리보기는 실제 팬 `PostDetailPage`에 현재 데이터를 주입한다. 접근 가능/잠김 상태를 비교하며 작성 중 입력과 목록 필터를 보존한다. 목업에서 스튜디오 게시물 저장을 팬 피드 fixture에 자동 발행하는 연결은 아직 제공하지 않는다.
- 출금 PIN·PASS는 [보안 계약](./withdrawal-security-pass.md)을 확인한다. `/preview`의 PIN은 체험용 메모리 상태이며 `/service`는 서버 proof·해시·일회용 출금 인증을 사용한다. 실제 PASS/은행 공급자 bridge는 미완료다.
- 매일 19:00 한국 시간 고아 미디어 배치는 [미디어 수명주기](./media-lifecycle.md)에 저장했다. 신규 worker 구현은 존재하며 삭제는 기본 off다. 운영 프로세스 등록/보존 정책/실제 삭제 검수는 별도다.
