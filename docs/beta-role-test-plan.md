### 공식 근거와 적용 판단

확인일2026-10-25. 사업 선택과 법률 의무를 구분하며 아래 근거로 외부 계약 승인을 추정하지 않는다.

- [Toss 테스트 키](https://docs.tosspayments.com/reference/using-api/api-keys): 테스트·운영 키를 구분하고 베타는 테스트 키만 받는다. 운영 키로 바꾸는 것만으로 테스트 구독을 재청구하지 않는다.
- [정보통신망법 제50조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029563135) 및 [시행령 제62조의2](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lspttninfSeq=81508): 광고 사전 동의, 표시/수신거부, 동의·철회 처리결과 요건을 분리했다. 2026-10-02 시행본 확인. 광고 큐와 필수 인증/거래 안내를 분리한다.
- [KISA 불법스팸 방지 가이드7차 개정](https://www.kisa.kr/401/form?postSeq=3608), [불법스팸대응센터](https://spam.kisa.or.kr/spam/main.do): 로그인 없는 무료 수신거부,2년 수신동의 확인을 적용한다.
- [RFC8058](https://www.rfc-editor.org/rfc/rfc8058): GET으로 수신거부를 실행하지 않으며 POST와 List-Unsubscribe 헤더를 준비한다. 실제 DKIM 헤더 서명/수신처 인식은 별도 검증한다.
- Mac의 `2026 개인정보 처리방침 작성지침.pdf`는 실제 처리 항목·기간·파기·국외이전 사실과 공개 문서 일치를 요구한다. 실제 미확정 값을 추정하지 않고 signupReady 차단 조건을 유지했다.

실제 사람에게 한 역할씩 맡기면 **운영자 포함 17명**이다. 운영자 본인이 A0를 맡으면 **참여자 16명 모집**이다. G0 때문에 사람을 한 명 더 모집할 필요는 없다. 자동화·초기 점검은 적은 인원이 17개 계정을 분리 운영할 수 있으나 실제 17명 동시 사용·네트워크·기기 검수를 대체하지 않는다.

17개는 기준점의 최소 계정 수다. 가입 실패·탈퇴/재가입·비활성 관리자·미성년/본인확인 실패는 일회용 계정 또는 격리 데이터로 별도 실행한다. 모든 비정상 상태를 동시에 유지하려면 그만큼 추가 계정이 필요하며 새 사람을 모집할 필요는 없다. 초대제를 선택하면 기준 17개와 일회용 검수용 이메일을 별도로 준비한다. 실제 주소/비밀번호는 문서나 Git에 저장하지 않는다.

## 준비물과 환경

- 계정별 Playwright BrowserContext 또는 별도 브라우저 프로필을 사용한다. 같은 프로필의 탭이나 일반 시크릿 창 여러 개를 독립 세션으로 가정하지 않는다.
- 최소 실제 iPhone Safari, iPhone Chrome, Android Chrome, PC Chrome에서 교차 검수한다. 화면 에뮬레이션과 실제 기기 결과는 별도 기록한다.
- 각 크리에이터에 공개 글, 레벨 1/2/3 이상 글, 특정 상품 전용 글, 초안, 예약 글, 숨김/삭제 글을 만든다. C0도 게시물과 멤버십은 존재하되 구독자는 0명으로 둔다.
- 이미지·재생 가능한 동영상 혼합 10개, 긴 본문, 댓글/답글, 댓글 OFF, 미디어 없음, 깨진 업로드 등을 준비한다. 실제 얼굴/민감 자료 대신 합성·비민감 테스트 자료를 쓴다.
- PASS 보류 계정은 본인/성인 미확인 상태다. 일반 콘텐츠에서 가입·구독 흐름을 검수하고, 성인 제한 콘텐츠는 차단 검수만 한다. 허용 검수는 격리된 공급사 대역 결과 또는 실제 본인확인 결과를 명확히 구분한다.
- 카드 정상/거절/분실·정지/승인 후 응답 유실, 은행 성공/실패/결과 불명은 공급사 대역으로 먼저 검사한다. 토스 테스트 상점과 실제 청구는 서로 다른 결과다. 이 계획만으로 실청구·송금을 실행하지 않는다.
- 운영 서버 시계나 기존 거래를 바꾸지 않는다. 기간 경과, 동시성, 장애 주입은 격리 테스트에서만 한다.

## 초기 상태 검수

1. C0/C2/C10 가입→크리에이터 등록→프로필·멤버십·콘텐츠 작성.
2. N0·S01~S12 가입. 구독 전에는 모두 공개 콘텐츠만 접근 가능해야 한다.
3. S01/S02가 C2, S03~S12가 C10에 테스트 결제를 완료한다. 실패 주문은 유효 구독으로 집계하지 않는다. 실제 청구는 하지 않는다.
4. 창을 새로 열어 크리에이터의 구독자 목록, 팬의 내 구독, 관리자 현재 유효 구독 건수를 대조한다. 예상은 0/2/10명·총 12건이다. 해지예약 중 기간이 남은 구독도 유효 권한에 포함한다.
5. 비교 기준점의 주문/구독/원장 식별자와 각 계정 상태를 기록한 뒤 다음 흐름을 실행한다. 이후 테스트로 구독 수가 바뀌는 것을 오류로 오인하지 않는다.

## 금액 대조 기준

가격은 테스트 데이터로 정하며 운영 상품 가격 결정이 아니다. 예를 들어 모든 초기 구독을 10,000원으로 두고 승인된 총 공제율 20%를 격리 정책에 적용하면 다음과 같다. 2026-10-25 선택에 따라 보류기간은 7일이며 PG 실제 입금·대사는 별도다. 아래 순수익은 크리에이터 본인의 세금·법정 원천징수 전 금액이다.

| 구분 | 첫 승인 결제액 | 수수료 | 크리에이터 순수익 |
| --- | ---: | ---: | ---: |
| C0 | 0원 | 0원 | 0원 |
| C2 | 20,000원 | 4,000원 | 16,000원 |
| C10 | 100,000원 | 20,000원 | 80,000원 |
| 합계 | **120,000원** | **24,000원** | **96,000원** |

- 정상 갱신 1건: 승인 누계 +10,000원, 수수료 +2,000원, 순수익 +8,000원. 신규 가입 수는 증가하지 않는다.
- 미사용 전액 환불 1건: 순매출 -10,000원, 수수료 -2,000원, 순수익 -8,000원. 누적 승인액과 순매출은 서로 다른 지표다.
- 해지예약: 그 시점의 매출·현재 결제 기간 수익을 임의 차감하지 않는다. 다음 갱신만 중지한다.
- 실패/불확실 승인: 확정 전 유료 권한과 매출을 성공으로 집계하지 않는다. 승인 조회로 복구되면 정확히 한 번 반영한다.
- PG 실제 정산액·입금일·세금·이체 비용은 위 애플리케이션 원장과 별도 대사한다.

## 현재 가입 개방과 검수의 차단 사항

- 가입 범위는 초기 17계정 초대로 확정했다. 실제 초대 명단은 아직 비어 있다. 2026-10-25 운영은 `email-only`로 전환했고, 코드 기본값은 여전히 `SIGNUP_IDENTITY_MODE=pass`다. 명시적인 `email-only`에서만 PASS UI/가입 증명을 보류한다. `SIGNUP_EMAIL_ALLOWLIST`는 서버에서 메일 발송과 가입 양쪽에 적용하고 명단은 클라이언트에 반환하지 않는다.
- 이메일 모드도 이메일 일회성 증명, 만19세 이상 조건 확인, 시행 가능한 문서 버전·동의를 검사한다. 실명은 빈 값, `identity_hash`는 null이며 클라이언트의 `identityVerified`/`adultVerified`를 믿지 않는다.
- 2026-10-25 질문지 조사 시 운영 법률문서는 공개본이고 `signupReady=false`였다. 탈퇴·파기 절차, 국외이전 실제 계약/국가/기간, 콘텐츠 정책이 미완료로 기록되어 있다. 일반 콘텐츠부터 베타를 시작한다는 선택만으로 실제 처리·문서가 변경되지는 않는다. PASS 보류 설정으로 문서 게이트를 해제하지 않으며 개방 전에 처리 절차·임시 가입 설명·시행본을 맞춘다.
- 수수료 20%·정산 보류 7일은 사업 정책으로 확정했다. 2026-10-25 운영 DB 정책 version2의2000bps/7일과 감사 이력을 적용·대조했다. 과거 null·미발행 기록은 당시 상태이며 현재 정책 미적용을 뜻하지 않는다. 실제 PG 입금·본인계좌/송금 검수는 별도다.
- PASS/은행 실제 연동이 없는 기능은 해당 실제 공급사 검수 완료로 기록할 수 없다. 이 계획과 17개 계정 준비만으로 출시 가능·무장애를 선언하지 않는다.
