# 출금 간편비밀번호와 PASS 본인확인

작성일: 2026-09-13. 로컬 목업의 흐름과 향후 운영 서버의 책임을 구분한다.

## 사용자 흐름

- 스튜디오에서 출금용 **숫자 6자리 간편비밀번호**를 설정하고 같은 번호를 다시 입력해 확인한다. 로그인 비밀번호와 별도 용도다.
- 미설정 상태에서는 출금 신청을 진행할 수 없으며 설정 화면으로 안내한다.
- 출금 금액·수령 계좌·잔액을 먼저 확인한 뒤 간편비밀번호를 입력한다. 검증에 성공한 해당 출금 요청만 접수한다.
- 오류는 입력 근처에 안내한다. 비밀번호는 화면을 닫거나 요청을 마치면 입력 상태에서 제거하며 URL·브라우저 영구 저장소·분석 이벤트·로그에 남기지 않는다.
- 비밀번호 변경·분실 재설정은 본인확인 정책이 연결될 후속 기능이다. 기존 비밀번호를 조회하거나 사용자에게 다시 보여주는 기능을 만들지 않는다.

## 현재 목업과 운영 연동의 경계

현재 `/preview/studio/security`와 출금 신청은 같은 `StudioFinanceModel`을 사용한다. 설정 상태, 설정 콜백, 출금 조건에 대한 비밀번호 검증 콜백을 주입받으며 실제 회원·은행·PASS API를 호출하지 않는다. 목업의 브라우저 메모리 상태는 실제 계정 보안으로 사용할 수 없다.

운영에서는 비밀번호 검증과 출금 권한 확인을 모두 서버가 수행한다. 클라이언트의 `pinConfigured` 또는 검증 성공 표시를 신뢰해 출금 요청을 승인해서는 안 된다. 새로고침이나 브라우저 저장소 조작으로 우회되지 않아야 한다.

## 운영 서버 계약 설계

1. 비밀번호는 서버용 비밀번호 해시와 사용자별 솔트로 보관한다. 원문 복호화·조회 API를 제공하지 않는다. 비밀번호와 검증 토큰은 요청/오류/분석 로그에서 제거한다.
2. 연속 실패 횟수와 대기 시간은 서버가 사용자·인증 시도 기준으로 관리한다. 브라우저 새로고침·다중 탭·다른 IP만으로 실패 이력이 초기화되지 않아야 한다. 운영 횟수·시간은 별도 정책으로 확정한다.
3. 비밀번호 검증 결과는 짧은 유효기간의 일회용 `authorizationId`로 제공한다. 인증 사용자, 출금 목적, 금액, 수령 계좌 및 계좌 변경 버전, 확인한 출금 조건에 연결한다.
4. 출금 요청 시 인증 사용자·권한·토큰 만료·금액/계좌 일치·계좌 확인 상태·잔액을 서버에서 다시 검증한다. 계좌나 금액이 바뀌면 재검증한다.
5. 권한 토큰 사용 처리와 출금 예약은 하나의 트랜잭션으로 수행한다. 같은 요청 식별자의 정상 재시도는 같은 접수 결과를 반환하며 중복 예약하지 않는다. 다른 요청에서 이미 사용한 권한 토큰을 재사용할 수 없다.
6. 설정·변경·재설정 및 출금 검증 성공/실패의 감사 기록에는 원문 비밀번호나 민감한 인증 응답을 포함하지 않는다. 비밀번호 재설정 시 기존 출금 권한 토큰을 무효화한다.

응답은 공통 `success`, `data`, `errorMessage`, `errorCode` 형식을 사용한다. `PIN_NOT_CONFIGURED`, `INVALID_PIN`, `PIN_LOCKED`, `AUTHORIZATION_EXPIRED` 등은 제안된 의미 구분이며 실제 오류 코드 명칭은 서버 계약에 맞춘다.

## PASS를 추가할 위치

| 진입 | 향후 필수 단계 | 서버가 확인할 것 |
| --- | --- | --- |
| 회원가입 | 가입 확정 전 PASS 본인확인 | 가입 시도와 인증 결과의 연결, 만료·재사용 여부, 중복 계정 정책 |
| 간편비밀번호 최초 설정 | 로그인 상태에서 PASS 본인확인 후 새 번호·확인 입력 | 해당 로그인 사용자와 본인확인 대상 일치, 설정 목적, 일회용 결과 소비 |
| 간편비밀번호 변경·분실 재설정 | 새로운 PASS 본인확인 후 번호 설정 | 재설정 권한, 만료·재사용 방지, 이전 출금 권한 토큰 무효화 |

**PASS 연동은 아직 구현하지 않는다.** 현재 화면에 본인확인 완료 배지나 완료 기록을 만들어 실제 PASS 검증처럼 표현하지 않는다. PASS 공급사·SDK·세부 요청 필드는 연동 시 공식 계약으로 확인한다.

본인확인 결과를 단순한 `true`로 전달하지 않는다. 서버가 발급한 가입/설정 시도 식별자와 `verificationId`, 목적, 대상 사용자, 만료 시각, 사용 시각을 관리한다. 공급사 콜백의 진위를 서버에서 검증한 뒤 결과를 기록하며, 브라우저 쿼리나 팝업 메시지 자체를 인증 증거로 삼지 않는다. 인증 결과 소비와 가입/비밀번호 설정을 원자적으로 처리한다.

본인확인 정보는 서비스에 필요한 최소 항목만 저장한다. 필요성이 확인된 식별 정보는 별도 보호 영역에서 관리하고 프론트·일반 관리자 목록에 공급사 원본 응답을 노출하지 않는다. 나이 제한·중복 계정 허용 범위·탈퇴 후 재가입 기준·정보 보관 기간은 사업 정책으로 별도 확정한다.

## 후속 검수 기준

- 비밀번호 미설정·불일치·잠금·만료·금액 변경·계좌 변경은 출금 접수로 이어지지 않는다.
- 올바른 번호를 확인한 해당 요청만 접수하며, 재시도·다중 탭에서도 중복 출금이 없다.
- 인증 결과 재사용, 다른 계정의 PASS 결과, 위조 콜백, 만료된 결과는 가입·설정에 사용할 수 없다.
- PASS 취소·실패·시간 초과 시 완료로 표시하지 않고 다시 시도할 수 있다.
- 숫자 키보드, 붙여넣기, 마스킹, 키보드 포커스, 오류 안내, 좁은 화면을 확인한다.
