## 멤버십 이미지

크리에이터는 멤버십 등록·수정에서 대표 이미지를 선택·교체·제거할 수 있다. 이미지가 없거나 로드에 실패하면 기본 카드로 표시한다. 스튜디오와 팬 페이지는 같은 이미지 표시 컴포넌트를 사용하고, 선택 상태와 이미지 주소를 데이터로 주입한다.

현재 목업은 로컬 파일을 브라우저에서 확인하며 실제 업로드 서버를 호출하지 않는다. 운영에서는 임시 업로드 후 발급받은 `mediaId`를 저장 요청에 전달한다. 서버가 소유자, 처리 완료 여부, 허용 형식·용량을 확인하고 멤버십 버전과 매핑한다. 클라이언트가 전달한 임의 URL을 영구 파일 식별자로 신뢰하지 않는다.

이미지는 버전의 선택 필드다. 교체하거나 현재 카드에서 지워도 과거 버전·구독 조건에서 참조하는 파일은 즉시 삭제하지 않는다. 과거 구독과 변경 이력을 재현하는 데 필요한 참조는 함께 보존한다.

## 데이터 구조

- 미디어: `id`, `ownerId`, `storageKey`, 형식·크기, 처리 상태, 생성 시각, 삭제 후보/격리 시각, 삭제 완료 시각.
- 미디어 참조: `mediaId`, 대상 종류, 대상 식별자, 대상 버전 식별자, 용도, 연결/해제 시각. 공유 참조를 지원하고 동일 연결은 중복 생성하지 않는다.
- 작업 기록: 실행 식별자, 시작/종료 시각, 후보·보류·삭제·실패 건수와 재시도 상태. 파일 URL이나 민감한 콘텐츠를 일반 로그에 남기지 않는다.

콘텐츠 본문뿐 아니라 아바타·멤버십 버전·임시저장·예약 게시물·댓글 첨부 등 실제 지원하는 모든 참조를 검사한다. 원본과 썸네일/변환본은 한 미디어에 연결하여 함께 정리하되 아직 변환 중인 작업은 보호한다.

## 매일 오후 7시 배치

요구 시간은 **매일 19:00, Asia/Seoul(한국 시간)**이다. 인스턴스의 운영체제 시간대에 맡기지 않고 스케줄러에 시간대를 지정한다. 여러 서버/재시작에서 동일 날짜 작업이 중복 실행되지 않도록 실행 잠금과 멱등 키를 둔다.

1. 업로드/변환 중인 파일과 보존 기간 내 임시 파일은 제외한다. 임시 파일 유예 기간은 운영 전 별도 확정하며, 미확정 상태에서 즉시 삭제하도록 구현하지 않는다.
2. 연결 대상이 삭제 처리됐거나 유효 매핑이 없는 미디어를 페이지 단위로 찾는다. 현재 상품에서 빠졌더라도 과거 버전·유효 구독·보관해야 할 기록에서 참조 중이면 제외한다.
3. 후보 표시 후 다시 참조 유무를 검사한다. 후보 상태의 파일을 연결할 때도 같은 잠금/상태 검사를 적용하여 검사와 삭제 사이에 새 매핑이 생기는 경쟁을 막는다.
4. 확정된 보존 정책에 따라 격리 후 저장소 파일을 삭제한다. 삭제 실패는 재시도하며, 저장소의 이미 없는 파일은 멱등 성공으로 처리한다. 저장소 삭제 완료 후 DB 상태를 완료로 변경한다.
5. 원본·파생 이미지 정리 결과를 기록한다. 실패/이상 급증을 운영 모니터링으로 알리고 다음 실행에서 이어 처리한다.

탈퇴·소프트 삭제·결제 기록 보존 정책과 참조 유지 범위는 서버에서 판단한다. 단순히 `deletedAt`이 존재한다는 이유만으로 모든 관련 파일을 삭제하지 않는다. 인벤토리의 DB 미등록 파일도 같은 유예·재검사 절차로 처리하며 저장소 전체를 무조건 삭제하는 경로를 두지 않는다.

## 후속 검수

- 새 업로드·저장 중·공유 참조·과거 버전의 이미지는 정리되지 않는다.
- 모든 참조가 해제된 파일만 유예/격리 후 정리된다.
- 정리 중 신규 연결, 작업 중단·재시작, 중복 실행, 저장소 실패에도 사용 중인 파일을 지우지 않는다.
- 첫 운영 적용은 삭제 없는 후보 집계로 시작하고 실제 참조와 대조한 뒤 삭제를 활성화한다.
